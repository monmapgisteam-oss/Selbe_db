# Даалгавар — CEO-гийн KPI самбарыг сэдэвчилсэн 5 ангилал + 3 түвшний гэрлэн дохио болгох

> Энэ бол Сэлбэ порталын (`Selbe_db-main`, Next.js + TypeScript) нүүр хуудасны
> удирдлагын самбарыг дахин зохион байгуулах даалгавар. Кодыг өөрчлөхөөс өмнө
> §0 (хориглох зүйл) ба §7 (шийдэгдээгүй асуулт)-ыг заавал уншина уу.

## 0. Хамрах хүрээ ба ХОРИГЛОХ зүйл

**Хамрах хүрээ:** зөвхөн нүүр хуудасны удирдлагын самбар — `Home.tsx` ба `ExecKpi.tsx`.
Газрын зураг, давхаргын каталог, бусад view (`plan`, `tsogts`, `gazar`, `analysis` г.м.)-д хүрэхгүй.

**ХОРИГЛОХ:**

1. **Шинэ ArcGIS хүсэлт НЭМЭХГҮЙ.** Одоо байгаа loader-ууд (`live.ts`, `execData.ts`, `execTriage.ts`, `Finance.tsx`) хангалттай. Самбарын бүтэц өөрчлөгдөж байгаа болохоос өгөгдлийн эх сурвалж өөрчлөгдөхгүй.
2. **Одоо байгаа гүйцэтгэлийн ачаалалтын оновчлолыг эвдэхгүй.** `ExecKpi` нь `dynamic(..., { ssr: false })`-ээр ачаалагддаг, `loadOverlaps`/`loadVariance` нь `afterIdle`-ээр хойшлогддог, `execTriage`-ийн ачаалагчид модулийн түвшинд кэшлэгддэг. Эдгээр нь бүгд гүйцэтгэлийн аудитын үр дүн — хэвээр үлдэнэ.
3. **Hex өнгө ШУУД бичихгүй.** Зөвхөн CSS хувьсагч: `var(--good)`, `var(--warn)`, `var(--bad)`, `var(--ink-3)`, `var(--hue)`. Тогтмол hex нь гэрэл/харанхуй горимд дагадаггүй.
4. **Хиймэл өгөгдөл, чимэглэлийн график зохиохгүй.** Бодит цуваа/харьцаа байхгүй бол графикийг ОРХИНО (`ExecKpi.tsx`-ийн `CardData.chart` дээрх дүрэм хэвээр).
5. **Гүйцэтгэлийн тооцооны логикт хүрэхгүй.** `loadBlockProgress`, `joinBagts`, `loadProjectProgress`-ын томьёог энэ даалгаварт өөрчлөхгүй (§7-г үз).
6. **i18n алгасахгүй.** Бүх шинэ мөрийг `tr('…')`-ээр дамжуулж, `src/i18n/en.ts`-д англи орчуулгыг нэмнэ.

## 2. Юуг өөрчлөх вэ

**Одоо:** хоёр тусдаа самбар зэрэгцэж байна.
`Home` = ангилалгүй 10 нүд (хэмжээ ба статус хольцолдсон) · `ExecKpi` = статусаар бүлэглэсэн 9 карт.

**Асуудал:**
- Ангилал байхгүй, зөвхөн статус бий. Улаан бүлэгт ХАБЭА-гийн осол, обьёмын зөрүү хоёр зэрэгцэж болно — огт өөр албаны, огт өөр шийдвэрийн зүйлс.
- Давхардал: газар чөлөөлөлт **гурван** газар (Home-ийн `clear`, Home-ийн `cleared`, ExecKpi-ийн `clearance`); гүйцэтгэл хоёр газар (`prog`, `schedule`).
- «158 га» гэх хэмжээний тоо статустай үзүүлэлттэй ижил харагдаж, «сайн уу муу юу» гэсэн утгагүй асуулт төрүүлж байна.

**Болгох:** НЭГ самбар · сэдэвчилсэн **5 ангилал** · ангилал бүрийн дотор үзүүлэлт бүр **3 түвшний өнгө**.

> **Гол зарчим: ангилал = СЭДЭВ (юуны тухай), өнгө = ТҮВШИН (хэр муу).**
> Хоёрыг хольж болохгүй. Одоогийн `TIERS`-ээр бүлэглэдэг логик УСТАНА — түүний
> оронд өнгө нь картын дотор (зурвас, цэг, шошго) илэрхийлэгдэнэ.

## 3. Таван ангилал ба тэдгээрийн үзүүлэлт

### 1 · Хамрах хүрээ — «Би юу барьж байна вэ?»

**⚠️ Энэ ангилалд гэрлэн дохио БАЙХГҮЙ.** Бүх нүд `neutral` (саарал/`--data` аяс).

| Үзүүлэлт | Эх сурвалж |
|---|---|
| Төслийн талбай (га) | `loadHeadline().areaHa` |
| Хүн ам · өрх | `loadHeadline().population` · `loadHousing().ail` |
| **Барилгын төлөв: Төлөвлөсөн / Баригдаж буй / Одоо байгаа** | `barilga` давхаргын `Barilga_ty` (≈231 / 113 / 24) — **ШИНЭ, одоо KPI-д алга** |
| Барилгын блок | `loadHousing().blocks` |
| Барилгажих талбай (м²) | `Барилгажсан_талбай` нийлбэр |
| Нийгмийн байгууламж | `loadSocial().totalN` |
| Ногоон байгууламж (га) | `loadHeadline().greenHa` |

### 2 · Мөнгө — «Хэдийг зарцуулсан, зөв үү?»

| Үзүүлэлт | Эх сурвалж |
|---|---|
| **Төсвийн юүлүүр** (шинэ нэгдсэн нүд) | `loadBudget()`: `total` (CF006) → `orderTotal` (CF012) → `contract` (CF023) → олгосон IPC (`finQ.data.given`) → `transferred` (CF028) |
| Гэрээлэлт vs биет гүйцэтгэл | `contract/total` % ба `loadProjectProgress().actual` |
| Санхүүжилт vs биет зөрүү | одоогийн `finance` карт |
| Обьёмын зөрүү (₮) | `loadVariance()` |

> Юүлүүр нь одоогийн «Нийт төсөв» + «Гэрээт дүн» гэсэн хоёр салангид нүдийг
> ОРЛОНО. Салангид тоонууд нь хоорондоо ямар хамааралтайг хэлдэггүй; юүлүүр нь
> хаана гацсаныг шууд харуулна.

### 3 · Хугацаа — «Хуваарьтаа явж байна уу?»

| Үзүүлэлт | Эх сурвалж |
|---|---|
| Төслийн жигнэсэн гүйцэтгэл | `loadProjectProgress().actual` |
| Хуваарийн биелэлт (хоцорсон багц) | одоогийн `schedule` карт (`lagOf`/`lagLevel`) |
| Барилга угсралтын гүйцэтгэл | `useBagtsTable()` — блокоор жигнэсэн |
| Үе шатын задаргаа (Бэлтгэл → Суурь → Каркас…) | `loadProjectProgress().byStage` — `neutral` |
| **Тайлангийн хамрах хүрээ** | `loadProjectProgress().coverage` (одоо ≈81.5%) — **ШИНЭ** |

### 4 · Саад — «Юу намайг зогсоож байна вэ?»

CEO-д хамгийн үнэ цэнтэй ангилал. Бусад дөрөв нь «юу болсныг», энэ нь «одоо юу хийхийг» хэлнэ.

| Үзүүлэлт | Эх сурвалж |
|---|---|
| Газар чөлөөлөлт — үлдсэн талбар/га | `loadClearance()` |
| Давхцсан нэгж талбар (багцаар) | `loadOverlaps()` |
| **Тайлан ирээгүй блок** | `useBagtsTable()` → `Σ missing` — **ШИНЭ** |
| **Уншигдаагүй багц (системийн эрүүл мэнд)** | `loadVariance().failedPkgs` — **ШИНЭ** |

### 5 · Хүн ба чанар — «Хэн хэр ажиллаж байна?»

| Үзүүлэлт | Эх сурвалж |
|---|---|
| ХАБЭА — осол, зөрчил | `incQ` (`queryGroup`) |
| ХАБЭА — хохирол | `loadDamage()` |
| Гүйцэтгэгчийн зэрэглэл | `useBagtsTable()` — **`neutral`**, гэрлэн дохио БИШ |
| Хот төлөвлөлтийн оноо | `useSuitability().avgScore` |

## 4. Гэрлэн дохионы дүрэм

Статусын төрөл **тав**, гэхдээ **өнгө нь гурав**:

| Төлөв | Өнгө | Хэзээ |
|---|---|---|
| `bad` | 🔴 `var(--bad)` | Босго давсан — яаралтай шийдвэр |
| `warn` | 🟡 `var(--warn)` | Дунд — хяналт хэрэгтэй |
| `good` | 🟢 `var(--good)` | Хэвийн |
| `neutral` | ⚪ `var(--ink-3)` / `var(--data)` | Хэмжээний үзүүлэлт — «сайн/муу» гэж дүгнэх боломжгүй |
| `unknown` | ⚪ `var(--ink-3)` + «өгөгдөл алга» | Өгөгдөл ирээгүй эсвэл ачаалагдаагүй |

**Дүрэм:**

1. **`unknown`-ыг `good` эсвэл `0` болгож ХЭЗЭЭ Ч харуулахгүй.** Тайлан ирээгүй блок нь 0% БИШ; `transferred = 0` нь «шилжүүлээгүй» гэсэн үг байж ч болно, «бөглөгдөөгүй» ч байж болно. Ялгааг ил гаргана.
2. **`neutral` нь хэзээ ч өнгөтэй болохгүй.** «158 га» улаан ч биш, ногоон ч биш.
3. **Ангиллын гарчиг = дотоод хамгийн муу түвшин + тоолуур.** Жишээ: `Саад  🔴 2 · 🟡 1 · 🟢 1`. Гарчгийн зурвасын өнгө = хамгийн муу түвшин. `neutral`/`unknown` тоологдохгүй.
4. **Ангиллын дотор эрэмбэ:** `bad` → `warn` → `good` → `neutral` → `unknown`. CEO эхлээд улааныг харна.
5. **Өнгө ГАНЦААРАА утга дамжуулж болохгүй** (WCAG). Дүрс эсвэл текст шошго дагалдана — жишээ нь `bad` дээр `!`, `warn` дээр `▲`, `good` дээр `✓`; эсвэл «Яаралтай / Анхаарах / Хэвийн» гэсэн жижиг шошго.
6. **Алдаатай карт** (`retry`) нь `bad` БИШ, `unknown` — «татагдсангүй» нь «муу байна» гэсэн үг биш. Одоогийн `notReady` нь алдааг `bad` болгодог — үүнийг засна.

## 5. Босгын хүснэгт

Кодод аль хэдийн байгаа тогтмолуудыг ХЭВЭЭР ашиглана (`VAR_BAD_MNT`, `DMG_BAD_N`, `lagLevel`). Шинээр тодорхойлсныг ⭐-аар тэмдэглэв.

| Үзүүлэлт | 🟢 good | 🟡 warn | 🔴 bad |
|---|---|---|---|
| Санхүүжилт vs биет зөрүү | \|зөрүү\| ≤ 5пп | ≤ 15пп | > 15пп |
| ⭐ Гэрээлэлт vs биет | гэрээлсэн% − биет% ≥ 0 | −10…0 | < −10 (гэрээгүй ажил) |
| Обьёмын зөрүү | зөрүүгүй | > 0, < 100 сая ₮ | ≥ 100 сая ₮ (`VAR_BAD_MNT`) |
| Хуваарийн биелэлт | хоцрогдолгүй | шар багц бий (gap ≥ 5) | улаан багц бий (gap ≥ 10) |
| ⭐ Тайлангийн хамрах хүрээ | ≥ 95% | 80–95% | < 80% |
| Газар чөлөөлөлт | ≥ 95% | 80–95% | < 80% |
| Давхцсан нэгж талбар | 0 талбар | — (§7-г үз) | ≥ 1 талбар |
| ⭐ Тайлан ирээгүй блок | 0 | ≤ 10% блокийн | > 10% |
| ⭐ Уншигдаагүй багц | 0 | 1 | ≥ 2 |
| ХАБЭА осол | 0 | ≤ 5 | > 5 |
| ХАБЭА хохирол | 0 | 1–2 | ≥ 3 (`DMG_BAD_N`) |
| Хот төлөвлөлтийн оноо | ≥ 65 | 45–65 | < 45 |

Босгыг **нэг тогтмолын файлд** төвлөрүүлнэ (жишээ нь `src/lib/kpiLevels.ts`) — картын дотор
шидэт тоо тараахгүй. Тогтмол бүрд «энэ тоо хаанаас гарсан» гэсэн нэг мөр тайлбар бичнэ.

## 7. ⚠️ Кодыг бичихээс ӨМНӨ хэрэглэгчээс асуух зүйлс

Эдгээр шийдэгдээгүй байхад самбар нь итгэл төрүүлэхгүй:

**A. Гүйцэтгэлийн ганц тодорхойлолт алга.** Системд одоо **гурван өөр тоо** зэрэг оршиж байна:
1. `loadProjectProgress().actual` — жигнэсэн төслийн явц
2. `execData.joinBagts` — багцын дундаж, **бүх блокоор** хуваасан (тайлангүйг 0%)
3. `BuildingPanel`/`Bagts` — багцын дундаж, **зөвхөн тайлагнасан блокоор**

`execData.ts`-ийн тайлбарт «МЭДЭГДЭЖ БУЙ ЗӨРҮҮ» гэж бичээстэй. CEO хоёр дэлгэц нээгээд
өөр хоёр тоо харвал бүх самбарт итгэхээ болино. **Аль нь CEO-гийн албан ёсны тоо вэ?**
(Санал: ганц `progressOf()` helper болгож гурван модульд хамт хэрэглэх.)

**B. «Нийт төсөв» аль нь вэ?** ЕТ-ийн нэгж үнийн тооцоо (барилга дангаараа ≈7.16 их наяд ₮)
ба батлагдсан төсөв (822 тэрбум ₮, зөвхөн 3 бүсэд) — хоёр огт өөр хамрах хүрээтэй. Багц-1
дээр 373 тэрбум vs 683 тэрбум гэж бараг хоёр дахин зөрж байна. Юүлүүрийн эхний шат аль нь вэ,
нөгөө нь хаана үлдэх вэ?

**C. Давхцсан талбарын дунд түвшин.** `execTriage.ts`-ийн тайлбарт «2026-08-21, хэрэглэгчийн
хүсэлт: давхцсан талбар БАЙВАЛ ШУУД Яаралтай — дундын түвшин байхгүй» гэж бичээстэй. Одоо
3 түвшний систем рүү шилжиж байгаа тул энэ үзүүлэлт хэзээ ч шар болохгүй. Энэ нь **зориудаар**
уу, эсвэл дунд түвшин нэмэх үү (жишээ нь 1–10 талбар → шар)?
